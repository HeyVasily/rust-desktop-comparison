Idle memory

Median memory of the application's whole process family (webview helpers included) with a 960×640 window, after 30 s settling and 120 one-second samples. All three panels share one scale.

How to read this. Each OS reports memory differently (Linux/macOS RSS, Windows Working Set), so compare toolkits within a panel. Summing RSS counts shared pages more than once, which inflates multi-process apps such as Tauri on Linux. Idle CPU stayed below 0.11 % of one core for every case — too small to rank. These are idle UI-only observations, not startup, interaction or frame-rate measurements.

    C builds a persistent widget tree; GTK signals call C callbacks.main.c
    GtkWidget *body = gtk_box_new(GTK_ORIENTATION_HORIZONTAL, 12);
GtkWidget *yards = gtk_box_new(GTK_ORIENTATION_VERTICAL, 4);
GtkWidget *scroll = gtk_scrolled_window_new();
projects = gtk_list_box_new();
gtk_widget_set_hexpand(scroll, TRUE);
gtk_scrolled_window_set_child(GTK_SCROLLED_WINDOW(scroll), projects);
gtk_box_append(GTK_BOX(body), yards);
gtk_box_append(GTK_BOX(body), scroll);
g_signal_connect(projects, "row-selected", G_CALLBACK(select_project), NULL);
    Declarative .slint markup; Rust supplies models and handles callbacks.main.slint
    ListView {
    for project in root.projects: Button {
        text: project.name + "                 NOT_CREATED";
        height: 38px;
        checkable: true;
        checked: root.selected-project == project.id;
        clicked => { root.choose-project(project.id); }
    }
}
    C++ creates QWidget layouts; Qt signals connect to lambdas.main.cpp
    auto *root = new QVBoxLayout(&window);
auto *body = new QHBoxLayout;
body->setSpacing(12);
auto *yards = new QWidget;
yards->setFixedWidth(200);
body->addWidget(yards);
auto *projectLayout = new QVBoxLayout;
auto *projects = new QListWidget;
projectLayout->addWidget(projects);
body->addLayout(projectLayout, 1);  // Expand the center column.
auto *details = new QLabel;
details->setFixedWidth(250);
body->addWidget(details);
root->addLayout(body, 1);

    Method and limits

    Workload

    • 10 synthetic yards, 100 projects, filter and Refresh — no backend, no polling.
    • 960×640 visible content, release builds, one app at a time.
    • 30 s settling, then 120 samples; CPU uses actual elapsed time.

    What it does not show

    • Startup time, interaction cost, frame rate or GPU rendering.
    • A controlled cross-OS ranking: runners, CPUs and toolkit builds differ.
    • Rust bindings for GTK or Qt: those examples are written in C and C++.
